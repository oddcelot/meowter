## Direction (not yet planned — maintainer's call)

1. **Navigation transaction** (→ plan 005): async `navigate()`, guards/redirects, loaders with `AbortSignal`, pending/error states, lazy route code. Biggest gap vs TanStack Router / Vaadin Router.
2. **Accessibility as a differentiator**: focus + live-region announce + per-entry scroll restoration + View Transitions opt-in. Cheap, and few web-component routers do it well.
3. **Typed, validated search params** via Standard Schema on top of the existing `searchParams` store.
4. **One matching model**: runtime is first-match by DOM order; only file-route codegen sorts by specificity. Ranked matching for all three definition styles before 1.0.

## Findings considered and rejected

- `navigate()` emits `route-change` even when the URL is unchanged: intentional (re-navigation to same URL updates state); not a bug.
- `#onPopState` resets the in-memory history list on unknown history ids: acceptable for entries created outside meowter; revisit in the 005 RFC (Navigation API makes it moot).
- Missing `README.md` content: real, but premature until the API settles after 005; fold into the 1.0 docs effort.
- Runtime `dependencies` (`node-html-parser`, `tinyglobby`) shipped to browser consumers: noted in plan 003 maintenance notes; split decision deferred.
